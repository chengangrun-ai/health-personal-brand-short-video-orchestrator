# content-and-copy — 通用内容与文案（内容层）

## 定位与分工

| 层 | Skill | 负责 |
|---|---|---|
| 人格层 | `brand-voice` | **像不像我** —— 表达风格、AI 味检测、禁用表达 |
| 内容层 | `content-and-copy`（本 Skill） | **内容本身** —— 写什么、什么结构、什么论证、什么标题 |
| 写法层 | `short-form-video-script` | **短视频怎么写怎么讲怎么拍** —— 时间轴、Hook、留存、分镜 |

**本 Skill 不定义个人表达风格，也不做短视频脚本。** 表达风格一律调 `brand-voice`；
逐字稿/口播一律转 `short-form-video-script`。

---

## 铁律

1. **不定义人设。**「像不像我」的问题一律交 `brand-voice`。
2. **不做视频脚本。** 用户要短视频 → 转 `short-form-video-script`（除非明确说「只改文字，不要变成视频」）。
3. **最终稿必过 AI 味检测**（`brand-voice` 检测模式），不通过就重写，不许只报告。
4. **不伪造我的经历。** 未经我确认的信息，不得写进内容资产库当作我的真实经历/案例/数据。
5. **不为「好看」牺牲真实。** 默认不追求高级、有格局、震撼、深度、专业、极具感染力。
6. **优先级顺序：** 真实 > 清楚 > 有观点 > 有记忆点 > 有传播性 > 华丽。

| 用户想要 | 转给 |

## 能力清单

| 操作 | 做什么 |
|---|---|
| 生成 | 一个主题 → 成篇内容 |
| 扩展 | 一个观点 → 扩成有论证的内容 |
| 优化粗稿 | 保留原意与真实表达，改结构、密度、清晰度 |
| 改写 | 换说法，不换意思 |
| 缩短 / 扩写 | 控字数，缩短不伤信息，扩写不加水 |
| 口语化 | 短句、自然停顿、呼吸感、允许不完整 |
| 增强表达 | 抽象→具体，弱→有力，去掉空洞形容词 |
| 调整结构 | 顺序、层级、段落切分；原 Skill 的 6 种结构见参考文件 |
| 提炼金句 | 从文中挑出可单独成立、可摘出来传播的句子 |
| 提炼标题 | 给多个不同方向的标题（不是同一句换词） |
| 多版本 | A/B/C（见下，**不强制**） |
| 跨平台 | 公众号 / 小红书 / 朋友圈 / 知乎 / 邮件 各自适配 |

**跨平台适配要点：**
- 公众号：结构清晰、小标题、可长，但开头不许铺垫
- 小红书：首句即钩子、短行、换行多、emoji 克制
- 朋友圈：短、私人语气、不许营销腔
- 知乎：论证 + 证据，允许长，但不许端着
- 短视频口播：→ 转 `short-form-video-script`

## 参考内容仿写

输入可以是：一篇文章 / 一段文案 / 一个帖子 / 一个短视频脚本 / 公众号文章 / 小红书笔记 / 朋友圈文案。

**先拆解 11 项**（缺哪项标「无」）：
`主题` / `核心观点` / `内容结构` / `Hook` / `论证方式` / `情绪` / `节奏` / `语言特点` / `金句` / `转折` / `CTA`

**只学三样：** 结构、逻辑、表达策略、内容组织方式。
**禁止：** 复制原句、复制对方的案例与数据、套用对方人设、沿用对方的具体说法。

产出必须是同结构不同内容 —— 素材换成我的（或换成通用可验证的事实），口吻过 `brand-voice`。

---

## 修改我的文案：六条规则

1. 原文已有我的个人表达特点 → **不许为了「变得更专业」抹掉它**
2. 只是语病问题 → **优先小改**，不动结构
3. 结构有问题 → 才调结构
4. 观点本身没问题 → **不许擅自改变观点**
5. 我说「保留我的原话」→ **尽可能保留原始表达**，最多动标点和不通顺处
6. 任何删改都要能说清为什么；说不清的，不改

输出改动对照表：`原文 → 改后 → 为什么改`。没改的地方说一句「这里保留原样，因为……」。

---

## 多版本（按需，不强制）

用户要版本对比时才给，或内容确实存在明显取舍时主动提议：

- **A 保守优化版**：最小改动，只修语病和逻辑
- **B 强传播版**：强化 Hook、金句、记忆点
- **C 强个人表达版**：最大程度贴近 `brand-voice` 档案里的真实习惯

默认只给一个版本。

## 与 short-form-video-script 协同

用户说「把这篇文章/这段内容变成短视频」时，走这条管道：

```
content-and-copy
  ↓ 提炼：核心观点 / 关键论据 / 可用案例 / 金句 / 目标人群 / 建议时长
short-form-video-script
  ↓ 生成：Hook 三选一 + 时间轴口播稿 + 留存设计 + 拍摄提示
brand-voice
  ↓ 检测：AI 味 10 项，不通过自动重写
```

本 Skill 只负责第一步，**不要自己造视频结构**。
用户明确说「只改文字，不要变成视频」→ 全程本 Skill 自己完成。

## AI 味检测（出最终稿前强制执行）

调用 `~/.workbuddy/content-system-foundation/brand-voice/SKILL.md` 的检测模式，重点查 11 项：

`套话` / `鸡汤腔` / `营销腔` / `公众号腔` / `过度总结` / `过度工整` /
`无意义的高级词` / `空洞形容词` / `AI 式排比` / `AI 式转折` / `不符合我真实说话习惯的表达`

黑名单见 `~/.workbuddy/content-system-foundation/brand-voice/references/ai-slop-checklist.md`。
**任一命中 → 自动重写，重写后复检。**

Voice Profile 未建立时只做通用检测，并标注「未经你的个人表达校验」，不阻塞交付。

## 内容资产库

长期沉淀在 `~/.workbuddy/content-assets/content-assets.md`，六个库：
**观点库 / 故事库 / 案例库 / 金句库 / 选题库 / 素材库**
（「表达库」不在这里 —— 归 `brand-voice` 的 voice-profile，唯一真相，不复制。）

**收录规则：**
- 每条记录格式：`内容 | 来源 | 状态 | 日期`
- 状态只有两种：**已确认**（我明确说过/写过/确认过）或 **待确认**（推断或转述）
- **待确认的不得在创作中被当作我的真实经历、真实案例、真实数据使用** —— 要用就先问我
- 我每次给素材、每次改稿，都顺手回写对应库

## 原始框架（5 个维度，保留自原 Skill）

内容强不强，看五维，任一维短板会拖垮整体：

1. **Hook** — 3–5 秒内赢得继续读。强 Hook：承诺具体价值 / 揭示张力 / 开一个环 / 反常识（且能撑住）/ 展示而非概述
2. **Structure** — 选一种结构并贯彻到底（问题→解法→证据 / 清单+论证 / 步骤 / 对比→推荐 / 故事→教训 / 问答→推论）
3. **Voice** — 由 `brand-voice` 提供，本 Skill 不定义
4. **Substance** — 具体、原创视角、可执行细节、诚实的取舍、真实例子
5. **Closing** — 收掉开头开的环 / 给明确下一步 / 落一句可被引用的话 / 回扣开头

参考文件：
- `references/original-content-and-copy.md` — 原 Skill 全文（5 维度详解、写作/编辑双工作流、失败模式）
- `references/content-brief-template.md` — 动笔前该有的 brief
- `references/content-edit-checklist.md` — 发布前编辑检查表

## 失败模式

- **自己定义人设 / 自己做视频结构** —— 越界到别的层
- **仿写变抄写**
- **把待确认信息当我的真实经历**
- **为了「专业」抹掉我的个人表达**
- **编辑靠加字** —— 强编辑通常是删
- **硬凑三版本 / 硬塞 CTA**
- **为好看牺牲真实** —— 违反优先级链
- **过渡生硬** —— 段落之间没有承接，读者被迫自己补逻辑
