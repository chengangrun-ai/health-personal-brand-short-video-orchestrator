# short-form-video-script — 短视频脚本（写法层）

## 定位与分工

| Skill | 负责 |
|---|---|
| `brand-voice` | **像不像我**（表达风格、AI 味检测、禁用表达） |
| `short-form-video-script`（本 Skill） | **这个视频怎么写、怎么讲、怎么拍**（结构、Hook、节奏、留存、时长、分镜） |

**本 Skill 不定义个人表达风格，也不自建人设。** 所有「像不像我」的判断一律委托 `brand-voice`。
本 Skill 也不负责选题 —— 选题由后续选题 Skill 提供。

上游：`content-and-copy` 在接到「把这篇文章变成短视频」时，负责提炼核心观点 / 论据 / 案例 / 金句，
再把素材交给本 Skill 生成脚本，它不自己造视频结构。

判断标准只有一条：**让一个真人愿意这样说，而且观众愿意继续听。**

---

## 铁律

1. **不定义人设。** 涉及个人风格 → 调 `brand-voice`，不要自己编。
2. **出最终稿前必过 AI 味检测。** 调 `brand-voice` 的检测模式，不通过就重写，不许只报告。
3. **不虚构。** 故事/街访模式禁止编造经历、数据、人物、结果。素材缺什么就列出来问，不许脑补。
4. **不过度优化。** 原稿够好就不大改；用户表达直接、不完美的地方不许修饰成标准文案。
5. **CTA 不需要就不加。** 不许为了结构完整硬塞。
6. **不预测数据。** 不说「这条会爆」。只说「这个结构通常更容易被看完」，并说明为什么。

## 输入 → 模式自动路由

| 输入特征 | 路由到 |
|---|---|
| 一个选题 / 观点 / 一句话想法 | 原创 |
| 给了参考视频、参考文案、爆款脚本，说「类似结构」「照这个来」 | 仿写 |
| 给了自己的原稿，要优化 | 改稿 |
| 书面文字，要求「能对着镜头说」「口语化」 | 口语化 |
| 一段真实经历 | 故事 |
| 一个需要论证的观点 | 观点 |
| 采访录音 / 文字 / 街访素材 | 街访/采访 |

判断不了 → 只问一次，问完直接做，不要反复确认。
给了参考素材但没说「仿写」→ 默认按仿写处理，并在开头说明判断依据。

## 七种模式

### 1. 原创
输入选题/观点 → 输出完整脚本。走下方「通用流程」。

### 2. 仿写
**先拆解，再重写。** 拆解九项，缺哪项标「无」：
`Hook` / `选题角度` / `冲突` / `信息结构` / `情绪变化` / `节奏` / `观点推进` / `金句位置` / `CTA`

只学三样：**结构、逻辑、表达策略**。
禁止：复制原句、复制对方的案例和数据、套用对方人设、沿用对方的具体说法。
产出：同结构 ≠ 同内容。新脚本的素材必须换成我的（或换成通用可验证的事实）。

### 3. 改稿
保留核心观点和真实表达，只优化：**开头 / 节奏 / 信息密度 / 逻辑 / 留存 / 结尾**。
- 输出改动对照表：`原文 → 改后 → 为什么改`
- 没改的地方也要说一句「这里保留原样，因为……」
- 原稿已经很好 → 直接说「不用改，可以直接拍」，最多提 1–2 个可选微调

### 4. 口语化
把书面文字改成能对着镜头说出来的话。要求：短句、自然停顿、口语、有呼吸感、**不要过度完整**、不像演讲稿、不像公众号文章。

手法：
- 长句拆断，一句话只留一个意思
- 书面词换口语词（「因此」→「所以」，「然而」→「但是 / 结果」）
- 标出停顿 `/`，标出重音 **加粗**
- 删掉连接词，允许句子不完整
- **保留一点「废话」** —— 全删干净就没呼吸感了

### 5. 故事
结构：`冲突 → 过程 → 转折 → 认知 → 结果`

硬约束：**不得虚构经历、数据、人物、结果。**
素材不够撑起某一环 → 明确列出「需要你补：___」，不许自己填。

### 6. 观点
结构：`Hook → 观点 → 论证 → 案例 → 转折 → 金句 → 结尾`

### 7. 街访 / 采访
从素材中提取：`原话` / `高价值回答` / `冲突` / `反差` / `金句` / `人物故事`

- 原话必须用引号原样标注，**不得改写后冒充原话**
- 输出：可剪辑的内容分点 + 口播串词（我把这些素材串起来的话）

## 时长

| 时长 | 口播字数 | 结构容量 |
|---|---|---|
| 15s | 50–70 | Hook + 1 个信息点 + 收尾 |
| 30s | 100–140 | Hook + 2–3 个点 + 金句 |
| 45s | 160–200 | Hook + 3 个点 + 一次转折 + 结尾 |
| 60s | 220–280 | Hook + 论证 + 案例 + 转折 + 金句 + 结尾 |
| 90s | 320–400 | 完整起承转合 + 1 个完整故事 |
| 3min | 650–800 | 多段落 + 2 个案例 + 2 次转折 |
| 5min | 1100–1300 | 完整叙事 + 3 个案例 + 分章节 |

**未指定时长** → 自动判断，并**用一句说明理由**。判断依据：
信息量有多大 / 需不需要案例 / 需不需要完整故事 / 观点是单一还是需要论证 / 平台默认。

## Hook 系统

**同一个选题给 3 个完全不同方向的 Hook**，跨 3 个不同 archetype（不是同一句换个词）。

可选方向（11 类）：
`冲突` / `反常识` / `悬念` / `故事` / `提问` / `数据` / `结果` / `对比` / `直接观点` / `人物事件` / `真实经历`

每个 Hook 写**三层**：
1. 口播第一句（Verbal）
2. 首帧画面（Visual）—— 静音、暂停在第一帧时也要成立
3. 字幕文字（Text）—— 3–7 个字

生成后逐个检查（四项全过才算合格）：
具体名词 /  payoff 可见或可推断 / 没有「开场白式废话」/ 第 3 秒内把钩子说完

引擎与反模式见 `references/hook-archetypes.md`、`references/three-layer-hook.md`、`references/hook-anti-patterns.md`。

## 留存设计（出稿必查）

四条硬检查：
1. **前 3 秒**有没有留下来的理由？
2. **第 10 秒左右**有没有新信息？（不然观众在这里划走）
3. **中间**有没有转折 / 冲突 / 新信息？
4. **结尾**有没有兑现开头的承诺？

三大失败模式（诊断每一稿）：`弱 Hook（1 秒就走）` / `无递进（中间泄气）` / `payoff 埋太深（中途停看）`
→ `references/retention.md`

**不许为了留存制造虚假悬念。** 钩子承诺了什么，正片必须兑现。bait-and-switch 是短视频里最快掉信任的做法。

## AI 味检测（出最终稿前强制执行）

调用 `~/.workbuddy/content-system-foundation/brand-voice/SKILL.md` 的检测模式，逐项检查 10 条：

1. 像不像真人讲话？
2. 符不符合我的真实表达习惯？（查 `~/.workbuddy/voice-profile/voice-profile.md` 的 K / L / N 段）
3. 有没有 AI 模板句？（查 `~/.workbuddy/content-system-foundation/brand-voice/references/ai-slop-checklist.md` 黑名单）
4. 过不过度工整？（三段式、等长句、通篇对仗）
5. 有没有大量抽象词？（认知 / 底层逻辑 / 方法论 / 闭环 / 势能……）
6. 像不像营销号？
7. 像不像鸡汤？
8. 有没有为了显得专业而故意复杂？
9. 有没有明显的「AI 总结腔」？
10. 有没有我平时不会说的话？（拿不准的词去 `corpus/` 搜，搜不到 = 越界）

**任一命中 → 自动重写，重写后复检，不许只报告。**

Voice Profile 尚未建立时：只做通用 AI 味检测，并在交付时明确标注
「本稿未经过你的个人表达校验，Voice Profile 建好后可再过一遍」。**不要因此阻塞交付。**

## 输出格式

默认严格按以下结构输出：

```
【视频标题】
【核心选题】
【目标人群】
【视频目的】
【建议时长】        ← 含选择理由
【Hook】            ← 3 个不同方向，每个含口播第一句 + 首帧画面 + 字幕文字
【正文】            ← 完整口播稿，带时间轴、停顿标记、重音
【关键转折】        ← 在第几秒改变节奏，改什么
【金句】            ← 可重点剪辑 / 上字幕的句子
【结尾】
【CTA】             ← 不需要就写「本条不需要 CTA」
【拍摄提示】        ← 镜头 / 场景 / 表情动作 / B-roll / 字幕重点 / 剪辑节奏
【AI 味检测】       ← 判定 + 命中项 + 已改处
```

**拍摄提示只给必要的。** 一条口播不需要导演脚本 —— 不写机位图、不写灯光、不写分镜表。

## 通用流程

1. 路由模式（判断不了只问一次）
2. 定时长（未指定则自动判断并说明理由）
3. 生成 3 个不同方向的 Hook（三层齐全）
4. 搭结构：Hook → Escalation → Payoff →（CTA）
   - 段落之间用「但是 / 所以」连接，不用「然后……然后」
5. 写口播稿，标时间轴、停顿、重音
6. 留存四查
7. AI 味检测 → 不通过则重写
8. 按输出格式交付

## 失败模式

- **自己定义人设** —— 那是 `brand-voice` 的活
- **仿写变抄写** —— 换了皮没换骨，一眼看出
- **虚构经历 / 数据 / 人物 / 结果** —— 故事和街访模式的红线
- **为留存造假悬念** —— 承诺不兑现，掉信任最快
- **过度优化** —— 把用户的原稿改成「AI 认为的好文案」，等于毁掉它
- **硬塞 CTA**
- **拍摄提示写成导演脚本** —— 用户要的是提醒，不是分镜表
- **承诺爆款** —— 只能说概率和原理，不能说结果
